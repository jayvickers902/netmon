# Refreshing the bundled OUI snapshot

netmon intentionally does not download vendor data at runtime, so the IEEE OUI
registry is bundled and refreshed by hand.

The bundle is the **complete MA-L registry**, prefix and organisation only —
roughly 39,700 entries and 1.2 MB. It was previously a hand-trimmed selection of
"vendors on the local network", which failed in the obvious way: the trimmed file
carried 26 entries and resolved **none** of the 18 devices on the network it was
supposed to cover, and any newly joined device would have resolved to nothing
regardless. Trimming was never the design principle here — not downloading at
runtime was. Carrying the whole registry costs about a megabyte in the wheel and
removes the failure mode permanently.

To refresh:

```bash
curl -sSL -o oui.txt https://standards-oui.ieee.org/oui/oui.txt
```

Parse the `(base 16)` lines, which carry the prefix already normalised to six
hexadecimal characters, and write `src/netmon/data/oui.csv` as:

```text
# IEEE OUI (MA-L) registry, prefix and organisation only.
001A11, Google
B827EB, Raspberry Pi Foundation
```

Notes on parsing:

- Normalise prefixes to six uppercase hexadecimal characters. The `(hex)` lines
  use `-` separators; the `(base 16)` lines do not.
- Collapse runs of whitespace in the organisation name.
- Skip entries whose organisation is `PRIVATE`. Those are filings that withheld
  the registrant, and they resolve to a vendor name that tells a reader nothing.
- Organisation names contain commas (`Samsung Electronics Co.,Ltd`). The loader
  splits on the first comma only, so no quoting is required.
- Write UTF-8; some organisation names are non-ASCII.

Then run `uv run pytest` and verify the wheel contains `netmon/data/oui.csv`
with `uv build`.

## What will still not resolve

Two categories, both correct behaviour rather than gaps in the data:

- **Randomised MACs.** If the second hexadecimal digit is `2`, `6`, `A`, or `E`,
  the locally-administered bit is set and the address was generated by the
  device, not assigned by a manufacturer. Modern phones do this by default. No
  registry will ever resolve them.
- **ARP artefacts.** `00:00:00:00:00:00` and `ff:ff:ff:ff:ff:ff` are the
  unspecified and broadcast addresses. They are not devices.
